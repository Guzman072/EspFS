# Phase 2 設計：Modbus RTU 唯讀通訊（ESP32 → TTL/RS485 → ZLAC8015D）

> **本檔只有設計**：沒有程式碼、不燒錄、不碰序列埠。使用者確認設計後才進入實作。
> 暫存器、位址、單位、頁碼以 `../PROJECT.md` 第 4 節為準；本檔不重複列表。手冊頁碼寫法同 `PROJECT.md`（`RS485 p.N`、`驅動器 p.N`）。
> 「設計預設」代表手冊沒寫、由本設計暫定的值，需實測調整，對應 `PROJECT.md` 第 8 節的待確認項目。
> **警語**：引用的手冊對應舊版硬體，與 V4.2 已知不同；位址、預設值、故障碼、LED 行為只作參考，未經實機驗證前不得當成事實（見 `PROJECT.md` 開頭）。

## 1. 範圍與安全邊界
| 項目 | 規定 | 依據 |
|------|------|------|
| 允許功能碼 | **只有 0x03** | AGENTS.md 規則 9；RS485 p.3 |
| 禁止 | 0x04、0x06、0x10 及其他所有功能碼；任何寫入；啟動馬達 | 規則 9 |

非目標：馬達控制、暫存器寫入、遙控器（i-BUS）整合、自動掃描 Slave ID 或 Baud、廣播位址 0。

## 3. 模組切分
純邏輯與硬體分離，純邏輯可在電腦上用 PlatformIO `native` 環境單元測試（不需要開發板）。

| 模組 | 內容 | 是否碰硬體 |
|------|------|-----------|
| `crc16` | CRC16 計算 | 否 |
| `frame` | FC 0x03 請求組裝、回應與例外回應解析 | 否 |
| `guard` | 送出前檢查：功能碼白名單、長度、Slave ID、數量與位址、CRC | 否 |
| `registers` | 候選暫存器表（位址、名稱、型別、單位、縮放） | 否 |
| `master` | 一次交易：送出、等待、驗證、重試 | 透過 `transport` 介面 |
| `transport` | UART2 的抽象介面（`transport.h`）；測試版本為 mock，真實版本見下方 `transport_serial2` | 否 |
| `report` | Serial 輸出格式化 | 否 |
| `poller` | 輪詢狀態機（BOOT → PROBE → POLLING → LATCHED），只透過 `master`、`transport` 介面與輸出介面運作 | 否 |
| `loopback` | A5 迴路測試邏輯（不經過 `master`） | 否 |
| `transport_serial2` | 真實 transport：包 `Serial2`，含第三層防線；只在 Arduino 環境編譯 | 是（唯一碰 `Serial2` 的檔案） |
| `poll_main`、`loopback_main`（`src/`） | 兩個很薄的進入點，只接 USB Serial 輸出 | 是 |

規則：只有 `transport` 的真實實作能呼叫 `Serial2` 寫入，且只在 `guard` 通過後。每個檔案預計 200–400 行以內。

## 4. 封包組裝（只允許 FC 0x03）
**請求（8 位元組）**：RS485 p.4。
| 位元組 | 內容 |
|--------|------|
| 0 | Slave ID（1–127；0 拒絕） |
| 1 | 0x03 |
| 2–3 | 起始位址（高位元組在前） |
| 4–5 | 暫存器數量 N（高位元組在前） |
| 6–7 | CRC16（**低位元組在前**） |

**正常回應（5+2N 位元組）**：Slave ID、0x03、位元組數（= 2N）、N 個暫存器（每個高位元組在前）、CRC16（低位元組在前）。
**例外回應（5 位元組）**：Slave ID、0x83、錯誤碼（0x01 非法功能碼／0x02 非法資料位址／0x03 非法資料值）、CRC16。RS485 p.3。

**組裝限制**
- 數量 N：1 到 16（設計預設；手冊沒寫上限，對應待確認項目 8），超出為 `REJECTED_LEN`。初次實測先用 N=1，再逐步增加。
- 位址越界（含位址加數量跨出允許範圍）為 `REJECTED_ADDR`；Slave ID 不在 1–127 為 `REJECTED_ID`。檢查順序：Slave ID → 數量 → 位址。
- 起始位址加數量必須落在允許範圍內：0x2000–0x2002、0x20A0–0x20AE（不含 20AFh）。**保留此位址範圍白名單**；要新增任何位址，必須先更新 `PROJECT.md` 並經使用者確認，才能修改白名單。
- 沒有通用的「組裝任意功能碼請求」函式。只提供一個 `buildReadRegisters(slaveId, startAddr, count)`，功能碼寫死為 0x03。不實作任何寫入請求組裝（0x06、0x10 的組裝程式不存在）。

**回應驗證順序**（任一步失敗即中止並回報對應狀態）
1. 長度 ≥ 5，否則 `SHORT_FRAME`。
2. CRC 正確，否則 `CRC_ERR`。
3. Slave ID 與請求相同，否則 `ADDR_MISMATCH`。
4. 功能碼為 0x03 或 0x83，否則 `BAD_FC`（回應端也套用白名單）。
5. 若為 0x83：回報 `EXC_01`／`EXC_02`／`EXC_03`（其他碼回報 `EXC_UNKNOWN`）。
6. 若為 0x03：位元組數 = 2N 且總長度 = 5+2N，否則 `BAD_LEN`。

## 5. CRC16
- Modbus RTU CRC16：初值 0xFFFF，多項式 0xA001（反射），涵蓋 CRC 之前所有位元組，低位元組先送。
- 已知答案測試向量（已在本設計階段用 Python 離線驗算）：

| 輸入 | CRC 值 | 送出順序 | 來源 |
|------|--------|----------|------|
| ASCII `123456789` | 0x4B37 | 37 4B | CRC-16/MODBUS 標準檢查值 |
| `01 03 20 AB 00 02` | 0x2BBE | BE 2B | RS485 p.4 |
| `01 03 04 00 64 00 64` | 0x07BA | BA 07 | RS485 p.4 |
| `01 03 20 A0 00 01` | 0xE88F | 8F E8 | 設計驗算（20A0h 讀 1 個） |
| `04 03 20 A0 00 01` | 0xBD8F | 8F BD | 設計驗算（Slave ID 4） |
| `01 03 20 01 00 01` | 0x0ADE | DE 0A | 設計驗算（讀 2001h） |
| `01 06 20 88 00 64` | 0xCB03 | 03 CB | RS485 p.4，**只作 CRC 與白名單拒絕測試，不得出現在任何送出路徑** |
| `01 10 20 30 00 02 04 04 00 00 00` | 0x4A68 | 68 4A | RS485 p.5，用途同上 |

## 6. 逾時與重試
手冊沒有規定回應時限與封包間隔，以下都是設計預設，需實測調整。

| 項目 | 設計預設 | 說明 |
|------|----------|------|
| 一個字元時間 | 約 86.8 µs（115200、8N1，10 位元：1 起始 + 8 資料 + 1 停止） | 計算值 |
| 送出前靜默 | 至少 2 ms | Modbus RTU 慣例：高於 19200 baud 時固定 1.75 ms，取 2 ms |
| 送出前動作 | 清空 UART2 接收緩衝 | 避免舊資料混入 |
| 送出後 | 等待 TX 完成（flush）後才開始計回應時限 | 自動流向模組在 TX 結束後切回接收 |
| 回應時限 | 100 ms，由 TX 完成起算 | 遠大於預期（N=16 時回應 37 位元組，約 3.2 ms）；實測後可縮短 |
| 回應結束判定 | 已收滿預期長度，或接收靜默 ≥ 2 ms | 例外回應長度固定 5 位元組 |
| 重試 | 逾時、`CRC_ERR`、`SHORT_FRAME` 最多重試 2 次（共 3 次嘗試） | 唯讀，重試安全 |
| 不重試 | 例外回應（驅動器明確拒絕）、`ADDR_MISMATCH`、`BAD_FC`、`BAD_LEN`、`REJECTED_*` | 直接回報；`REJECTED_*` 另會立即 `LATCHED`（見下列） |
| 重試間隔 | 20 ms | |
| 連續失敗上限 | 連續 3 個交易最終失敗 → 進入 `LATCHED`，停止輪詢，輸出摘要，等使用者處理（重啟） | 不自動恢復 |
| 失敗的定義 | 一個交易（含重試）最終狀態不是 `OK` 即為失敗，**包含例外回應**（`EXC_01`／`EXC_02`／`EXC_03`／`EXC_UNKNOWN`）、`ADDR_MISMATCH`、`BAD_FC`、`BAD_LEN`、`TIMEOUT`、`CRC_ERR`、`SHORT_FRAME`。任何一次 `OK` 把連續失敗計數歸零 | |
| `REJECTED_*` | **立即 `LATCHED`**（不累計次數）。代表程式送出了不合法的請求，是程式錯誤，不是通訊問題。記錄原因代碼（保留第一個原因，不被後續覆蓋），輸出該筆 `T` 行（`attempts=0`，`rtt_ms` 與 `values` 為 `-`）與 `S,ms,LATCHED`，之後**不再送出任何請求**（包含合法請求）；已 `LATCHED` 時詢問會回報進入 `LATCHED` 的原因 | 不自動恢復，需重啟 |
| 輪詢週期 | 200 ms（5 Hz）；上限 10 Hz | 見下方「狀態機與交易時間」 |
| `TX_FAIL` | transport 沒有寫完整個請求（第三層防線拒絕、線路一直忙碌、寫入不完整）。**立即 `LATCHED`**，行為同 `REJECTED_*`；不重試、不累計次數 | 與 `REJECTED_*` 的差別只在原因代碼 |
| 回音 | 收到的 8 位元組與剛送出的請求**逐位元組完全相同**，才視為回音並丟棄；只有開頭相同、其餘不同的資料不算回音，照一般回應驗證 | 保險機制；自動流向模組通常不回音 |

**狀態機與交易時間**：單次交易最壞情況約 340 ms（3 次嘗試 × 100 ms 回應時限 + 2 次重試間隔 × 20 ms），大於 200 ms 輪詢週期。狀態機同一時間只能有一筆交易進行中，**不得重疊送出**：下一筆交易要等上一筆（含重試）完全結束後才開始；若上一筆超過週期，下一筆立即開始或依週期對齊，但絕不並行。

**Slave ID 探測**：首次連線只送兩次探測（先 ID 1，再 ID 4），探測讀取 20A0h 1 個暫存器；兩者皆逾時 → 停止並回報，不嘗試其他 ID，不改 Baud，不使用廣播位址。V4.2 的 Slave ID 以暫存器 2001h 實測為準，不是 DIP 開關；因此不得撥動 DIP 來改 ID。

**探測成功後的額外讀取**：找到 Slave ID 後、進入 `POLLING` 之前，主程式自動讀一次通訊設定：2001h 起 2 個暫存器（Node ID 與 Baud 代碼），再讀 2000h 1 個（離線時間），用來確認實際 Slave ID 與 Baud（待確認項目 6、7）。這兩筆失敗不會阻止進入 `POLLING`，但計入連續失敗。只有探測回 `OK` 才算找到 Slave ID；回例外回應仍換下一個候選 ID。兩個候選都沒有 `OK` → `LATCHED`，原因記最後一次狀態。

**輪詢區塊**：每 200 ms 依序讀 5 個區塊，同一時間只有一筆交易，上一輪沒結束就不開始下一輪：

| 順序 | 位址 | 數量 | 內容 |
|------|------|------|------|
| 1 | 20A1h | 1 | DC voltage |
| 2 | 20A2h | 3 | Motor state、Hall state、Motor temperature |
| 3 | 20A5h | 2 | Error code（左、右） |
| 4 | 20A7h | 4 | 位置（左、右，各高低 16 位元） |
| 5 | 20ABh | 4 | 速度與轉矩（左、右） |

單次最多 4 個，在待確認項目 8（單次上限）實測之前保守使用。區塊表是 `PollerConfig` 的編譯期設定；任何位址仍須在 `registers` 白名單範圍內，否則 `REJECTED_ADDR` 立即 `LATCHED`。

## 7. Serial 輸出格式
USB Serial 115200，純文字 CSV，每行一筆；欄位內不含逗號與空白。`#` 開頭為註解行。啟動時輸出一次表頭。

| 類型 | 格式 | 說明 |
|------|------|------|
| `T`（交易結果） | `T,ms,slave,fc,addr,count,status,attempts,rtt_ms,values` | `values` 為 `位址=十六進位值` 以 `;` 連接；位址一律 4 位十六進位、不帶 `h`；無資料填 `-` |
| `D`（解碼值） | `D,ms,name,value,unit` | 依 `PROJECT.md` 第 4 節縮放：20A1h 0.01 V、20ABh／20ACh 0.1 r/min、20ADh／20AEh 0.1 A；32 位元位置值**暫定，組合方式未驗證**，原始暫存器值保留在 `T` 行，不以 `D` 行為準 |
| `S`（狀態） | `S,ms,state` | 主程式：`BOOT`、`PROBE`、`POLLING`、`LATCHED`；A5 迴路程式：`LOOPBACK`、`DONE` |
| `L`（A5 迴路測試） | `L,ms,index,verdict,rx_len,rx_hex` | 只有 A5 程式輸出。`verdict` 為 `PASS`、`FAIL_NO_BYTES`（沒收到任何位元組）、`FAIL_SHORT`、`FAIL_EXTRA`、`FAIL_MISMATCH`、`FAIL_NOT_SENT`；`rx_hex` 為收到位元組的連續十六進位（大寫、無分隔），無資料填 `-`。結尾輸出 `# SUMMARY pass=N fail=M total=T result=PASS\|FAIL` |
| `#`（原始位元組，可選） | `# TX 01 03 20 AB 00 02 BE 2B` | 預設關閉，除錯時才開 |

`status` 值：`OK`、`TIMEOUT`、`SHORT_FRAME`、`CRC_ERR`、`ADDR_MISMATCH`、`BAD_FC`、`BAD_LEN`、`EXC_01`、`EXC_02`、`EXC_03`、`EXC_UNKNOWN`、`REJECTED_FC`、`REJECTED_ADDR`、`REJECTED_LEN`、`REJECTED_ID`、`REJECTED_CRC`、`TX_FAIL`。`TX_FAIL` 表示 transport 沒有把整個請求寫出去，沒有任何請求被當成已送出；與 `REJECTED_*` 一樣立即 `LATCHED`。

範例（`OK` 那兩行的數值取自手冊 p.4 的讀取範例，其餘為格式示意；都不是實測資料）：
```
T,12345,01,03,20AB,2,OK,1,4,20AB=0064;20AC=0064
D,12345,actual_velocity_L,10.0,r/min
T,12600,01,03,20A0,1,TIMEOUT,3,-,-
T,12700,01,04,20A0,1,REJECTED_FC,0,-,-
```

A5 迴路程式的 `L` 行範例（格式示意，不是實測資料）：
```
L,200,1,PASS,8,010320A000018FE8
L,400,2,FAIL_NO_BYTES,0,-
```

## 8. 功能碼白名單（防線設計）
目標：任何非 0x03 的請求，在寫入 UART 之前就被拒絕。三層防線：

1. **組裝層**：只有 `buildReadRegisters`，功能碼寫死為 0x03。沒有寫入請求的組裝函式，也沒有接受「功能碼」參數的通用函式。
2. **送出層（`guard`）**：所有要送出的位元組，在 `transport` 寫入前必經 `guard`，檢查：
   檢查順序如下，第一個不過的即回報：
   1. 長度不足 2 位元組 → `REJECTED_LEN`（無法判讀功能碼）
   2. 功能碼（第 2 個位元組）不在白名單 `{0x03}` 內 → `REJECTED_FC`（先於其他檢查，使 13 位元組的 0x10 封包也回 `REJECTED_FC`）
   3. 長度不是剛好 8 位元組 → `REJECTED_LEN`
   4. Slave ID 不在 1–127 → `REJECTED_ID`
   5. 數量不在 1–16 → `REJECTED_LEN`；起始位址加數量不在允許範圍 → `REJECTED_ADDR`
   6. CRC 不符（避免被截斷或改動的封包）→ `REJECTED_CRC`

   任何一項不過：記錄 `T` 行、不寫入 UART、不重試，且 `master` 立即進入 `LATCHED`（見第 6 節）。
3. **傳輸層**：只有 `transport_serial2.cpp`（真實實作）能碰 `Serial2`，其 `write` 內用獨立的 `isReadFunctionFrame` 再檢查一次功能碼 0x03（雙重保險），不合格就不寫、回傳 0 並計數。另外寫入前會清空接收緩衝並確認線路連續靜默 2 ms（最多等 100 ms，等不到就放棄不送），寫入後 flush。`guardedWrite` 發現 transport 沒有寫完整個封包（含上述兩種情況與寫入不完整）一律回 `TX_FAIL`，`master` 與狀態機立即 `LATCHED`。

白名單是編譯期常數，沒有任何序列指令、設定或旗標可以在執行時修改它。

## 9. 測試策略（TDD，先寫測試）
全部在電腦上以 `native` 環境執行，使用 mock `transport`，**不接任何硬體、不燒錄**。目標涵蓋率 ≥ 80%（CLAUDE.md 與 ECC 測試規範）。

| 類別 | 測試內容 |
|------|----------|
| CRC | 第 5 節全部已知答案向量；單一位元翻轉會改變 CRC |
| 組裝 | `buildReadRegisters(1, 0x20AB, 2)` 逐位元組等於 `01 03 20 AB 00 02 BE 2B`；數量 0、17（`REJECTED_LEN`）、位址 0x2003（`REJECTED_ADDR`）、Slave ID 0 與 128 都被拒絕 |
| 解析 | 手冊回應 `01 03 04 00 64 00 64 BA 07` 解出兩個 0x0064；例外回應 `01 83 02` 加 CRC 解出 `EXC_02`；CRC 錯誤、截斷、長度不符、錯誤 Slave ID、錯誤功能碼各對應正確狀態 |
| 白名單 | 對功能碼 0x00–0xFF 逐一測試，只有 0x03 通過；其餘 255 個全部 `REJECTED_FC`，且 mock `transport` 的寫入位元組數必須為 0。第 5 節 FC 0x06 與 0x10 的完整封包（含正確 CRC）也必須被拒絕 |
| 逾時與重試 | 假時鐘；全無回應 → 3 次嘗試後 `TIMEOUT`；第 2 次回應正確 → `OK` 且 `attempts=2`；例外回應不重試；連續 3 次失敗（含例外回應）→ `LATCHED`；`OK` 使計數歸零 |
| `REJECTED_*` 與 `LATCHED` | 每一種 `REJECTED_*`（位址、數量 0 與 17、Slave ID 0 與 128）都立即 `LATCHED`、transport 寫入位元組數為 0、原因代碼正確；`LATCHED` 後合法請求也不送出且回報原因；原因不被覆蓋；輸出 `T` 行（`REJECTED_*`、`attempts=0`）與 `S,ms,LATCHED`。破壞驗證：讓 `REJECTED_*` 不 latch，這些測試必須失敗 |
| `TX_FAIL` | transport 回 0（拒絕）或寫入不完整（少一個位元組）→ `guardedWrite` 回 `TX_FAIL`；`master` 立即 `LATCHED`、不重試、原因代碼為 `TX_FAIL`；`poller` 在探測時遇到也立即 `LATCHED` |
| 迴路與狀態機 | `loopback`：短接（mock 回音）50 次全 `PASS`；無回音、過短、過長、內容不符、寫入被拒各對應正確 `verdict`。`poller`：ID 1 成功、ID 1 失敗改 ID 4、兩者皆失敗 `LATCHED`、週期 200 ms 不重疊、只寫 FC 0x03 與白名單位址、`REJECTED_*`／連續 3 次失敗／`TX_FAIL` 都 `LATCHED` 且之後不再送出 |
| 輸出 | `T`、`D`、`S` 行逐字比對；縮放（0.01 V、0.1 r/min、32 位元位置〔暫定〕、高低位元組拆分）正確 |
| 回音 | 與請求完全相同的 8 位元組被丟棄；開頭相同但其餘不同的資料不被丟棄 |
| 靜態檢查 | 建置前以腳本搜尋原始碼：`Serial2.write`（含 `Serial2.print` 等任何寫入 UART2 的呼叫）只能出現在 `transport` 的真實實作檔，出現在其他檔案即判失敗 |
